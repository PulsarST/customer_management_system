# customer_management_system

Management system for working with customer orders — встраиваемый чат‑виджет AI‑консультанта магазина.

Пользователь общается в чате → бэкенд формирует промпт с каталогом и историей → LLM возвращает структурированный JSON (`intent`: chat / products / cart / submit) → фронтенд рендерит сообщения, карточки товаров и корзину.

## Стек

- **Backend:** Go, [Gin](https://github.com/gin-gonic/gin), [gorilla/websocket](https://github.com/gorilla/websocket), [sqlx](https://github.com/jmoiron/sqlx), SQLite (чистый Go — [modernc.org/sqlite](https://modernc.org/sqlite), без CGO/gcc), [sashabaranov/go-openai](https://github.com/sashabaranov/go-openai).
- **LLM:** OpenAI‑совместимый эндпоинт NVIDIA (`integrate.api.nvidia.com`).
- **Frontend:** ванильный HTML / CSS / JS (без сборки).

## Требования

- Go ≥ 1.26 (CGO **не** нужен — драйвер SQLite на чистом Go).
- Токен NVIDIA `integrate.api` для работы чата.

## Настройка

Скопируйте шаблон и впишите токен:

```bash
cd backend
cp .env.example .env
# отредактируйте .env: AI_TOKEN=nvapi-...
```

Переменные окружения (все опциональны, кроме `AI_TOKEN`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AI_TOKEN` | Токен NVIDIA integrate.api | — (без него чат вернёт понятную ошибку) |
| `AI_MODEL` | Модель чата | `meta/llama-3.1-8b-instruct` |
| `DB_PATH` | Путь к `mockup.db` | автопоиск |
| `FRONTEND_DIR` | Путь к папке `frontend/` | автопоиск |
| `PORT` | Порт сервера | `8080` |

> Для более сильных рассуждений (но в ~2–5 раз медленнее) можно задать `AI_MODEL=qwen/qwen3-next-80b-a3b-instruct`.

## Запуск

```bash
cd backend
go build -o bin/server.exe ./cmd
./bin/server.exe
```

Откройте **http://localhost:8080/** — сервер сам отдаёт фронтенд с того же origin. Нажмите 💬 и напишите, например, «какие есть ручки?».

Проверка живости: `GET /healthz` → `ok`.

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/data/products` | Список товаров |
| `GET` | `/api/v1/data/storages` | Список складов |
| `GET` | `/api/v1/data/stocks` | Остатки по складам |
| `WS`  | `/api/v1/ws/chat` | WebSocket‑чат с AI |
| `GET` | `/healthz` | Healthcheck |

## Структура

```
backend/
  cmd/main.go                     — точка входа
  internal/
    routers/                      — маршруты + раздача статики
    services/                     — REST‑хендлеры и WebSocket‑чат
    handlers/ai/                  — формирование промпта и разбор ответа LLM
    handlers/db/                  — доступ к SQLite + рендер каталога для промпта
    chat/                         — сессии, история, корзина
    models/                       — модели данных
frontend/                         — чат‑виджет (index.html, script.js, style.css)
```

## Изменения в этой ветке (`futures`)

Полный разбор исходной версии, исправление критических багов, оптимизация скорости и качества ответов.

### Критические баги
- **Сервер падал при первом подключении клиента** — `ConnectToAI` вызывал `log.Fatalf` при отсутствии `.env`. Теперь `.env` опционален, при отсутствии токена клиент получает корректный `503`, сервер продолжает работать.
- **Гонка данных** — глобальная карта сессий и поля сессии менялись из нескольких горутин без синхронизации (`concurrent map writes`). Добавлены мьютексы и безопасные геттеры.
- **Сервер запускался только из `backend/`** — относительный путь к БД. Теперь путь ищется вверх по дереву (от исполняемого файла и от рабочего каталога) с переопределением через `DB_PATH`.
- **`fmt.Errorf` без использования** (ошибки `go vet`) — мёртвый код удалён.

### Архитектура и качество кода
- Драйвер SQLite `mattn/go-sqlite3` (CGO, нужен gcc) → **`modernc.org/sqlite`** (чистый Go).
- БД открывается один раз (общее соединение через `sync.Once`) вместо открытия/закрытия на каждый запрос.
- Сервер раздаёт фронтенд с того же origin (+ `/healthz`).
- Серверная проверка пустой корзины перед `submit`.
- Поиск `.env` вверх по дереву каталогов — токен подхватывается из любого каталога запуска.
- Удалён мёртвый код (`whatsapp.go`, `customer_message_handler.go`, неиспользуемые хелперы) и мусор (отладочный бинарь, `*.pid`). Добавлен `.env.example`.

### Frontend
- `timestamp` отправляется как RFC3339‑строка (раньше ломал разбор `time.Time` на бэкенде).
- Уникальный `sender` для каждого браузера через `localStorage` (раньше все делили одну серверную сессию).
- WebSocket‑URL берётся из origin страницы, а не зашит на `localhost`.
- Окна корзины больше не дублируются; «Очистить» сбрасывает корзину.

### Скорость ответа
- Каталог в промпте: JSON‑дамп (~11k токенов) → компактный **TSV** + легенда категорий + свёрнутые остатки (~6k токенов).
- История диалога ограничена последними сообщениями (раньше росла без предела).
- Payload товаров урезан до `{product_name, price}`.
- У HTTP‑клиента LLM добавлен таймаут (защита от зависаний).
- Модель по умолчанию → `meta/llama-3.1-8b-instruct` (после бенчмарка; ~2–5× быстрее), с настройкой через `AI_MODEL`.

Итог: типичный ответ ускорился с ~5–9 с до ~1–3 с.

### Качество ответов
- Промпт переписан: поле `text` — живой ответ на языке пользователя, без повторения вопроса; правила релевантности (без дублей и товаров не по теме).
- `MaxTokens` поднят (длинные списки больше не обрываются на середине JSON → нет «пустых» ответов).
- Graceful‑fallback: при некорректном JSON от модели пользователь видит вежливое сообщение, а не пустой экран.
